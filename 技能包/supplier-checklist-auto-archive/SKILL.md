# 通用版-供应商资料清单自动归档（模块2）

## Overview

上传任意甲方「资料要求/审核项清单」Excel（无论有无序号、列数多少、列名是什么、有无合并单元格），自动完成：表格结构自适应解析 → 合并单元格补全 → 自动生成层级序号 → 匹配资料库台账内资质/资料文件 → 按分类创建文件夹 → 复制重命名归集文件副本 → 输出汇总表。全程只读源库，输出全为副本。

## 硬性安全约束（永久锁定，违反即失败）

1. **仅明确指令触发**：只在用户明确发送「执行【通用版-资料清单自动归集归档】模块」时激活。未明确调用时遇到 Excel 文档，一律沿用模块1（supplier-shortlist-filing）的填表逻辑，禁止擅自触发本模块的建文件夹、复制归集逻辑。
2. **模块边界**：本模块只处理「资料要求/审核项清单类 Excel」；需要填写公司信息、资质信息的调查表 Excel 归模块1处理，不得混用。
3. **只读源库**：全程只读访问 `E:\卫华供应商入围资料库`，禁止修改、移动、删除库内任何源文件；所有输出均为副本。
4. **禁止编造**：匹配仅以两份台账为唯一依据；台账缺失、解析错乱、识别不到核心列 → 告警停止，禁止主观猜测、编造文件、虚构执行成功。
5. **强制复核提示**：所有交付物必须置顶标注：
   `【本结果由AI辅助生成，包含部分来自台账备注、别名的候选备选文件，候选文件不一定满足甲方要求，务必人工逐条甄别筛选，剔除无关文件，补充缺失资料后，才可对外提交，不可直接使用归集出来的全套文件】`

## 权威数据源（固定绑定，仅2份）

| 台账 | 关键字段 |
|---|---|
| `E:\卫华供应商入围资料库\供应商入围资料清单.xlsx` | 文件名、文件完整路径（存在拼接错误，脚本按文件名递归搜索修复）、备注 |
| `E:\卫华供应商入围资料库\资质清单.xlsx` | 类别、证书完整名称、文件路径（资料库内相对路径）、状态、备注 |

匹配语料分两层：
- **主匹配语料**（参与 ✅/⚠️）= 证书完整名称/文件名 + 类别；
- **候选字段语料**（仅参与 📎）= 备注 +（若存在）甲方常用别名。列不存在或为空时自动跳过，不编造；此时应向用户说明「📎 候选依赖台账备注/别名字段，补充后自动生效」。

## 标准工作流程（两阶段，中间必须人工确认）

### Step 1 — 自适应解析 + 输出预览（必须先做）

```bash
"$PY" "<skill目录>/scripts/parse_checklist.py" --input <甲方Excel> --out <工作输出目录>
```

脚本自动完成：
- 读取所有工作表，选数据量最大的表；补全合并单元格内容到每一行；
- 表头行仅在前 3 行内探测（表头不可能位于表格中部，防止分类文字含「指标/评价」等关键词的行被误判为表头、导致其上方数据被丢弃——2026-08-31 实测修复）；
- 同一分类下与上一行完全相同的要求（原表要求列合并单元格的产物）自动折叠为一条编号，折叠数在预览中标注；
- 自动识别【分类列】（合并单元格/重复层级列，如「供应商管理(8分)」「HSE绩效考核指标体系(6分)」）与【要求列】（具体资料要求/审核项/评价方式，如「查看合格供方名单」「核对相关证书」），不预设固定列数/列名/序号列，原有序号列自动忽略；
- 自动生成层级序号：第一个分类下 1、1.1、1.2……第二个分类下 2、2.1、2.2……；
- 产物：`解析预览.xlsx` + `parsed_items.json` + 控制台 markdown 预览表。

**强制人工确认门**：将解析预览表完整展示给用户（序号、补全后的分类名称、要求内容），等待用户确认无误后才允许执行 Step 2。解析识别不到【要求列】→ 脚本告警退出，此时向用户告警并停止，禁止继续；识别不到【分类列】→ 预览中标注⚠️警告，请用户在确认时一并裁决。

### Step 2 — 匹配 + 归集（确认后执行）

```bash
"$PY" "<skill目录>/scripts/match_and_archive.py" --items <工作输出目录>/parsed_items.json \
    --base "E:\卫华供应商入围资料库"
```

匹配规则（禁止无依据判定，结果分 4 类）：
- 先从要求文本提取**资料关键词**：剥离「查看/核对/现场查看」等动词前缀、去掉「相关」虚词、剥离「2分：」类评分标记、统一「台帐→台账」异体字，复合要求（顿号/逗号分隔）按片段（≥4字）分别匹配；
- **✅ 已匹配**：关键词片段与台账名称/类别双向包含（片段≥4字），标注文件本地绝对路径；多条命中时列出全部候选供人工挑选；
- **⚠️ 语义模糊匹配**：名称层面相似度达标（最长公共子串覆盖率≥3字 + 双字元 Dice，阈值 0.5），高亮需人工复核；纯泛词（如「相关证书」「相关报告」）不做模糊挂靠；
- **📎 台账字段候选文件**：名称匹配失败后，检索台账「备注」「甲方常用别名」字段——片段字眼包含（≥3字）或相似度≥0.45（候选仅供人工甄别，阈值略宽、宁多勿漏）即列为候选；**候选仅归集备选，绝不判定为符合要求**；
- **❌ 无匹配**：标注「资料库缺失，需手动补充」。

归集规则（安全第一）：
- 在**桌面**新建总文件夹【本次资料归集输出】，内部按每行【分类列名称】创建子文件夹；
- 仅 `shutil.copy2` 复制副本，绝不移动/修改/删除源库文件；副本重命名为【序号-原文件名】（如 `1.1-合格供方名单.pdf`）；
- 📎 候选文件前缀额外加「【候选-人工甄别】」：如 `1.1-【候选-人工甄别】企业征信报告.pdf`；同一行多份候选**全部**放入该条目文件夹，留待人工筛选剔除；
- ✅ 项与 📎 候选项默认归集；⚠️ 模糊项待人工确认后，用 `--confirm-fuzzy <序号列表>` 重跑归档（输出目录幂等，重命名冲突自动加后缀，不会覆盖已有文件）；用户明确指令**跳过人工确认环节**时，改用 `--auto-fuzzy`：全部模糊项自动归档，但强制带【候选-人工甄别】前缀并在汇总表标注「须人工甄别」——自动归档 ≠ 确认匹配。
- `--evidence` 佐证扩展模式：对 ❌ 无匹配项将模糊阈值降至 0.30，捞取低置信度佐证候选（如「客户投诉处理流程」→《客户投诉处理程序》、「售后管理流程」→《售后服务管理制度》），全部带【候选-人工甄别】前缀并标注「低置信佐证候选」。适用于用户明确要求「文件夹里装满实际文件」的场景；阈值放宽后仍无匹配的条目属资料库真缺文件，如实告知，禁止硬塞。

产物：
- `桌面\本次资料归集输出\<分类>\序号-原文件名`（及📎候选带前缀）文件夹结构，按序号排序；
- `桌面\本次资料归集输出\资料归集完成汇总表.xlsx`：序号、分类名称、要求内容、匹配结果（📎 行明确标记来源是台账备注/甲方常用别名及字段原文）、文件原路径、输出文件夹路径、人工复核确认栏；📎 行紫色高亮整行；一行多份候选文件时每文件一行（序号重复便于筛选）；首行红色置顶 AI 复核提示。

### 异常处理

- 台账加载失败/为空 → 告警停止；
- 匹配后 ⚠️+❌ 占比过高（如超过一半）→ 输出结果同时向用户高亮提示「匹配模糊度过高，请检查解析或台账」；
- 任何操作无法实现 → 如实告知，禁止虚构成功。
