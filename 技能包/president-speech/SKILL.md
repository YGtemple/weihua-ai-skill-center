# 总裁表彰大会发言稿

## 目标与边界

写出符合具体会议场景、具有集团总裁经营判断、执行抓法和现场动员感的发言稿，而非通用企业总结或历史稿换皮。

- 历史讲话只学习写法，不自动继承旧事实、旧数据、旧主题、旧姓名和旧议程。
- 公共风格保持稳定，场景结构允许变化，单篇新经验先验证再沉淀。
- 公司事实以当期正式材料为准；缺失时用 `[待核：事项]`，不编造。
- 默认输出可直接宣读的自然讲话正文，不带 Markdown 标题、写作说明或编辑批注。
- 总裁讲话突出经营结果、关键矛盾、责任机制和行动闭环，不写成纯战略致辞或部门流水账。

## 铁律：所有最终成果统一交付 Word

1. 完整稿、大纲、片段、改写稿、审校稿和征求意见稿均须生成可编辑 `.docx` 并交付，不得只在对话中贴正文。
2. 用户另要其他格式时，仍先交付 Word 主文件，其他格式只作附加产物。
3. 开始读取、新建或编辑 Word 前，完整读取内置 `word` Skill 的 `SKILL.md` 并按任务路由读取对应 workflow；多轮对话中的每条新指令均重新读取。
4. 正式净稿不含 Markdown、写作说明、编辑括注和待核占位。征求意见稿可保留 `[待核：事项]`，并在 Word 文末逐项说明。
5. 最终文件使用清晰中文名称和 `.docx` 后缀。

## 五层架构

| 层级 | 资源 | 职责 | 后续优化边界 |
|---|---|---|---|
| 公共调度层 | 本 `SKILL.md` | 任务分流、共同原则、工作流程、加载规则 | 只放跨场景稳定规则，避免堆入单场会议要求 |
| 场景模块层 | `references/annual-commendation.md`、`references/meeting-scenarios.md` | 年度表彰及季度、半年度、收官、专项动员等结构 | 可独立新增或调整场景，不影响其他模块 |
| 风格资产层 | `references/style-guide.md` | 总裁稳定语气、叙事、句式、经营表达和禁忌 | 只沉淀跨多篇讲话反复出现的特征 |
| 事实核验层 | `references/fact-rules.md` | 数据期间、单位、口径、人物奖项、强判断和外部事实核验 | 新口径追加规则，旧数据不得固化为未来事实 |
| 经验进化层 | `references/learning-loop.md`、`references/experience-log.md` | 新稿学习、候选经验、验证推广、失效退出 | 保留追加空间；候选、验证、核心、退役分级管理 |

## 按需加载

1. 每次起草、改写或审校完整发言稿，完整阅读 `references/style-guide.md`。
2. 年度总结表彰大会读取 `references/annual-commendation.md`；季度、半年度、四季度、收官及专项活动读取 `references/meeting-scenarios.md`。复合会议按主场景加载，必要时补读附加场景。
3. 材料或稿件包含数字、比例、排名、金额、奖项、项目、人物承诺或宏观事实时，完整阅读 `references/fact-rules.md`。
4. 用户提供新发言稿要求学习、吸收、优化，或根据使用反馈迭代本 Skill 时，完整阅读 `references/learning-loop.md` 和 `references/experience-log.md`。
5. 只加载本次任务需要的模块，不为“完整”而一次性读入全部参考文件。

## 工作流程

### 1. 判断任务类型

- **新写**：从场景、事实和大纲开始。
- **重写**：保留用户明确要求的观点，按新素材重建大纲，不机械换年份和数字。
- **润色**：保留原事实、结构和详略，只调整语气、句式和现场感。
- **压缩或扩写**：优先调整案例、背景和解释段落，不靠增删口号改变篇幅。
- **学习新稿**：进入经验进化流程，不直接起草，也不把单篇特点立即写成公共硬规则。

### 2. 确认场景与约束

识别会议主目的、讲话时点、听众、议程、时长或字数、讲话人姓名。信息不完整但不影响推进时采用保守默认；领导姓名、职务、出席人员、表彰名单和议程未知时不猜测。

先区分主场景与附加场景，例如“半年度大会暨管理提升推进会”以半年度复盘为主、专项动员为辅，避免两套完整结构平行拼接。

优先取得当期经营数据、工作总结、重点项目、表彰材料、会议议程和已批准部署。用户要求正式净稿但缺少关键材料时集中询问；用户接受征求意见稿时以待核标记推进。

### 3. 建立素材台账

逐一读取当期材料，记录事实、期间、单位、范围、目标或实际、来源位置、状态和拟用段落。区分最终值、阶段累计、预测值和目标值；区分集团、重机、重装及产品子项。

素材优先级：当期最终经营数据及指标口径；当期项目、技术、质量、交付、市场、管理、人才和文化事实；当期表彰名单与先进事迹；已批准部署；历年讲话仅作风格和战略延续参考。

### 4. 形成发言判断与功能大纲

先用内部四问确定主线：

1. 这次会议最需要统一什么认识；
2. 哪些成绩、先进经验或问题必须讲透；
3. 当前最重要的经营矛盾是什么；
4. 会后希望干部员工采取什么行动。

再按场景模块列出段落功能、事实证据和详略。结构是默认起点而非硬性枷锁，用户指定结构时从其要求。

### 5. 起草与审校

- 以“我们”凝聚共同奋斗，以“我”表达总裁判断、安排和责任，以“全体卫华人”发出行动要求。
- 用概括句统率事实，用短句下判断、提要求。
- 成绩、问题、形势和部署之间形成因果，不做部门材料流水账。
- 部署体现总裁抓经营、责任、机制、协同和结果，不停留于“加强、提升、持续”。
- 依次完成事实核验、场景核验、风格核验、编号文字核验和宣读核验。

完整成稿后，在生成 Word 前运行：

```bash
python scripts/speech_lint.py <发言稿.txt> --scene general
```

按实际场景将 `general` 替换为 `annual-commendation`、`quarterly`、`half-year`、`year-end` 或 `mobilization`。年度表彰大会默认篇幅可使用：

```bash
python scripts/speech_lint.py <发言稿.txt> --scene annual-commendation --min-chars 5000 --max-chars 7000
```

用户指定篇幅时调整参数；需要打破年度表彰会默认结构时加 `--free-structure`；征求意见稿加 `--allow-placeholders`。脚本只检查形式，不能替代事实和语感审校。

## 持续优化触发器

出现以下任一情况时，除完成当前写作任务外，按经验进化模块评估是否更新：

- 用户提供新的合适发言稿并明确表示学习、吸收或优化；
- 用户指出某类表达“更像”或“不像”总裁；
- 同一场景出现新的稳定结构或新的经营数据口径；
- 实际使用证明某条规则过严、过时或影响发挥。

只记录可复用规律，不把某次会议的临时事实、个别措辞偏好或一次性安排固化为长期规则。
