# 董事长发言稿 Skill

## 目标与边界

写出符合具体会议场景、具有董事长经营判断和现场动员感的发言稿，而非通用企业总结或历史稿换皮。

- 历史讲话只学习写法，不自动继承旧事实、旧数据、旧主题和旧议程。
- 公共风格保持稳定，场景结构允许变化，单篇新经验先验证再沉淀。
- 公司事实以当年正式材料为准；缺失时用 `[待核：事项]`，不编造。
- 默认输出可直接宣读的自然讲话正文，不带 Markdown 标题、写作说明或编辑批注。

## 铁律：所有最终成果统一交付 Word

1. 本技能产生的完整稿、大纲、片段、改写稿、审校稿、征求意见稿及其他发言稿相关最终成果，必须生成可编辑的 `.docx` 文件并通过文件交付工具交付；不得只在对话中贴正文，也不得以 Markdown、TXT、PDF、飞书或豆包在线文档替代 Word。
2. 用户另要其他格式时，仍必须先交付 Word 主文件，其他格式只能作为附加产物。
3. 开始新建、读取或编辑 Word 前，必须完整读取内置 `word` Skill 的 `SKILL.md`，并按任务路由读取对应 workflow；Windows 环境下遵循内置 `word` Skill 自身的 `references/workflows/windows-compat.md`，本专用 Skill 目录不复制该文件。多轮对话中的每条新指令均须重新读取。
4. 写作与形式检查可使用临时 `.txt` 中间文件，但不得作为最终交付。正式净稿不含 Markdown、写作说明或编辑批注；征求意见稿如需附待核说明，应附于 Word 文末。
5. 最终文件使用清晰的中文名称和 `.docx` 后缀。

## 按需加载

1. 每次起草、改写或审校完整发言稿，完整阅读 `references/style-guide.md`。
2. 年度总结表彰大会（含年初表彰大会，即上一年度总结表彰）读取 `references/drafting-patterns.md`；季度、半年度、收官及专项活动读取 `references/meeting-scenarios.md`。复合会议同时读取相关部分，以用户指定的主场景为准。
3. 材料或稿件包含数字、比例、排名、金额、奖项、项目、人物承诺或宏观事实时，完整阅读 `references/fact-and-data-rules.md`。
4. 用户提供新发言稿要求学习、吸收、优化，或根据使用反馈迭代本 Skill 时，完整阅读 `references/learning-loop.md` 和 `references/experience-log.md`。
5. 只加载本次任务需要的模块，不为“完整”而把所有参考文件一次性读入。

## 工作流程

### 0. 方向确认（每次必做）

直接调用本 Skill 时，先用一句话确认：本次任务是为**集团董事长**起草或审校发言稿，并确认会议场景。若上游调度已完成同一任务的身份与场景确认且上下文未变，不重复提问。

若判断本次任务不是董事长讲话（例如用户明确要总裁/总经理发言），立即停止并询问用户，**不自动跳转或加载总裁 Skill**，由用户决定下一步。

### 1. 判断任务类型

- **新写**：从场景、事实和大纲开始。
- **重写**：保留用户明确要求的观点，按新素材重建大纲，不机械换年份和数字。
- **润色**：保留原事实、结构和详略，只调整语气、句式和现场感。
- **压缩或扩写**：优先调整案例、宏观背景和解释段落，不靠删加口号改变篇幅。
- **学习新稿**：进入经验进化流程，不直接起草，也不把单篇特点立即写成公共硬规则。

### 2. 确认场景与约束

识别会议主目的、讲话时点、听众、议程、时长或字数。交付格式固定为 Word，不再询问或默认其他载体。信息不完整但不影响推进时采用保守默认；领导姓名、职务、出席人员、表彰名单和议程未知时不猜测。

先区分主场景与附加场景，例如“半年度大会暨管理提升推进会”以半年度复盘为主、专项动员为辅，避免两套结构平行拼接。年度总结表彰大会默认听众为集团全体员工、受表彰集体和个人；家属是否出席未知时不写家属致辞。

### 3. 建立素材台账

逐一读取当年经营数据、工作总结、重大项目、先进案例、会议议程和已批准部署。内部记录事实、期间、单位、范围、来源位置、状态和拟用段落。

素材使用优先级为：当年最终经营数据及指标口径；当年项目、技术、质量、交付、市场、管理、人才和文化事实；当年表彰名单与先进事迹；已批准部署、下一年预算与战略安排；历年讲话仅作风格和战略延续参考。不得因已有历史样稿而跳过当年附件。

区分最终值、阶段累计、预测值和目标值；区分集团、重机、重装及产品子项。历史样稿中的事实只作线索，回到当年材料核实后使用。

### 4. 形成发言判断与功能大纲

先用内部三问确定主线：

1. 这次会议最需要统一什么认识；
2. 哪些成绩或问题必须讲透；
3. 会后希望干部员工采取什么行动。

再按场景模块列出段落功能、事实证据和详略。结构是默认起点而非硬性枷锁：素材不支持默认结构时不硬凑，用户指定结构时从其要求。

### 5. 起草与审校

- 以“我们”为主要叙事主体，用概括句统率事实，用短句下判断、提要求。
- 成绩、问题、形势和部署之间形成因果，不做部门材料流水账。
- 部署体现董事长抓方向、边界、干部和机制，不重复经营层的全部细项。
- 每个重点至少落到一项已核实的行动、机制或结果指向。
- 依次完成事实核验、场景核验、风格核验和宣读核验。

完整成稿后，在生成 Word 前运行（将引号内文件名替换为实际发言稿路径）：

```bash
python scripts/speech_lint.py "发言稿.txt" --scene general
```

年度总结表彰大会改用以下命令；用户指定篇幅时按指定范围调整参数：

```bash
python scripts/speech_lint.py "发言稿.txt" --scene annual-commendation --min-chars 4500 --max-chars 7000
```

需要采用三部分、五部分以外的自定义结构时加 `--free-structure`。征求意见稿可加入 `--allow-placeholders`，但须在 Word 文末逐项说明待核内容，正式净稿不得保留占位符。脚本只检查形式，不能替代事实和语感审校。完成检查后，严格按内置 `word` Skill 的新建或编辑流程生成并交付 `.docx`。

## 持续优化触发器

出现以下任一情况时，除完成当前写作任务外，按 `learning-loop.md` 评估是否更新经验层：

- 用户提供新的合适发言稿并明确表示学习、吸收或优化；
- 用户指出某类表达“更像”或“不像”董事长；
- 同一场景出现新的稳定结构或新的经营数据口径；
- 实际使用证明某条规则过严、过时或影响发挥。

只记录可复用规律，不把某次会议的临时事实、个别措辞偏好或一次性安排固化为长期规则。
