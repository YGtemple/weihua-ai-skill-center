# 新发言稿学习与 Skill 进化规则

> **适用范围**：本文件仅适用于 chairman-speech（董事长发言稿）Skill 的经验进化。禁止将本文件沉淀的规则、经验或结构回写、迁移到总裁/总经理发言稿 Skill；跨角色经验回写须独立验证，不得直接套用。

## 目录

- 触发与原则
- 新稿学习流程
- 经验分级与回写
- 冲突和失效处理
- 更新后验证

## 一、触发与原则

当用户提供新的合适发言稿并要求“学习、吸收、借鉴、优化 Skill”，或实际使用反馈揭示稳定改进点时，启动本流程。

坚持四条原则：

1. **完整阅读再学习**：不得只凭标题、摘要或几段精彩句子提炼规律。
2. **事实与写法分离**：学习结构、语气、论证和现场处理，不把旧事实带入未来稿件。
3. **候选经验先验证**：单篇特点默认进入候选区，不直接改写公共硬规则。
4. **追加优先、最小改动**：保留已有有效规则，只修改明确受益的模块。

## 二、新稿学习流程

### 1. 登记语料

在 `experience-log.md` 的语料登记表追加：语料编号、文件或来源、讲话日期、场景、材料版本、学习状态。重复语料不重复登记，版本不明时标注待核。

### 2. 判断是否适合学习

优先考虑：同一讲话人、正式采用稿、完整稿、场景明确、表达质量高、具有新场景或新写法的材料。

谨慎或暂缓：仅提纲、未经确认的草稿、与他人风格混合且无法区分、质量明显不稳定、只有零散摘句的材料。用户指定必须学习时可提取局部经验，但标明局限。

### 3. 做五层拆解

| 观察层 | 提取内容 | 候选去向 |
|---|---|---|
| 场景层 | 开场方式、主体结构、详略、结尾、议程衔接 | `drafting-patterns.md` 或 `meeting-scenarios.md` |
| 风格层 | 稳定语气、论证、句式、人物温度、战略表达 | `style-guide.md` |
| 事实层 | 指标口径、数据表达、强判断证据、风险边界 | `fact-and-data-rules.md` |
| 质量层 | 编号、篇幅、文字规范、场景要素和编辑痕迹 | `speech_lint.py`，只加入可确定检查 |
| 公共流程层 | 跨场景反复出现且影响执行的方法 | `SKILL.md`，从严控制 |

同时记录“不应学习”的内容：临时事实、一次性比喻、特定领导分工、过时政策、口误、编辑批注、仅适用于该次会议的安排。

### 4. 生成原子经验卡

每条经验只表达一个可复用规律，追加到 `experience-log.md`，包含：

- 经验编号与状态；
- 来源语料与简短证据；
- 规律及适用条件；
- 不适用边界或失效风险；
- 拟回写模块；
- 验证记录。

证据优先用短摘录或段落定位，不把整篇讲话复制进经验文件。

### 5. 回写与验证

按经验状态决定动作，见下节。更新后运行 Skill 结构校验；修改检查脚本时同步做正反例测试。最后用一项代表性写作任务检查新规则是否提高质量、是否造成过度约束。

## 三、经验分级与回写

| 状态 | 含义 | 默认处理 |
|---|---|---|
| 候选 candidate | 来自单篇新稿或单次反馈，尚未验证 | 只追加经验卡，不改公共规则 |
| 已验证 validated | 有两篇以上独立同类语料支持，或经一次实际起草并获得用户明确认可 | 可回写对应场景模块；公共风格仍需谨慎 |
| 核心 core | 跨场景或多篇讲话稳定出现，且实际使用有效 | 可进入公共风格或事实规则；少数进入主流程 |
| 退役 retired | 被新口径替代、适用面过窄或证明效果不佳 | 保留记录和退役原因，从生效规则中移除 |

用户明确要求“立即把这条写成规则”时可直接回写，但仍登记来源、状态和适用范围，便于后期修正。

## 四、冲突和失效处理

- 新稿与旧稿风格不同，先判断是场景差异、讲话人风格演变，还是稿件质量差异，不以后者自动覆盖前者。
- 同一规则有两种合理写法时保留场景条件，不强求唯一模板。
- 新数据口径只更新事实层，不改董事长公共风格。
- 新场景只有一篇样稿时先形成候选结构，不急于在场景模块新增硬规则。
- 发现旧规则过严时优先改为”默认/可选/按需”，而非换成另一套僵硬限制。
- 禁止跨角色回写：从董事长发言稿沉淀的经验不得直接迁移到总裁/总经理发言稿 Skill；反之亦然。跨角色经验须经独立语料验证后方可参考。

## 五、更新后验证

每次正式优化后完成：

1. 检查 `SKILL.md` 的名称、描述和按需加载链接仍准确；
2. 确认新增内容只位于一个主要模块，避免多处重复；
3. 运行 `quick_validate.py`；
4. 修改 `speech_lint.py` 时运行合格稿与问题稿测试；
5. 在经验卡记录验证结果；无效优化回退到原规则，经验卡保留原因。
