# 卫华会议纪要

## 第 0 步：方向确认（每次必做）

1. 本 Skill 直接被调用时，先用一句话向用户确认本次是要"会议纪要"以及具体会议方向（月度例会／季度全员大会／半年度大会／管理提升活动／节后收心会等），不要默认会议类型。
2. 若 `weihua-dispatch` 刚完成同一任务的方向确认且上下文未变，不重复提问。
3. **本 Skill 只交付会议纪要，不起草讲话稿。** 用户实际要的是集团总裁或集团董事长在某次大会上的独立发言稿时，本 Skill 不起草、不扩写、不自动跳转或加载其他专用 Skill；请用户重新确认所需方向。
4. 纪要中涉及总裁／董事长讲话的段落，一律采用第三人称纪实归纳（"集团总裁要求……""集团董事长强调……"），**不加载讲话稿 Skill、不套用讲话稿风格扩写**。

## 核心原则

把完整录音、逐字稿和会议材料转化为**完整、准确、精炼、可执行**的正式会议纪要。完整覆盖有效发言，但不堆砌口语；历史纪要只提供结构、语言和版式，不为本次会议补充事实。

始终遵守：

- 当前会议材料决定事实，用户指定模板决定样式；二者冲突时分别处理，不得混用。
- 不编造发言人、职务、部门、议题、指标、项目、数字、日期、责任分工、表彰名单或领导要求。
- 不从录音开头、结尾或智能摘要推断"已经听完整"；必须核验完整时间范围。
- 不因精简而删除有效议题、关键案例、具体数字、部署动作或跟踪事项。
- 未获得的信息使用 `××` 占位或列入待核项，不得用历史值冒充分本次会议事实。

## 一、路由并读取专用规范

1. 月度公司例会、重机公司例会：读取 [monthly-meeting.md](references/monthly-meeting.md)，`meeting_type` 取 `monthly`。
2. 季度全员大会、半年度全员大会、管理提升启动／推进大会：读取 [quarterly-meeting.md](references/quarterly-meeting.md)，`meeting_type` 取 `quarterly`。
3. 节后收心会、工作动员会等专项会议：读取 [quarterly-meeting.md](references/quarterly-meeting.md) 第 6 节"专项会议变体"，`meeting_type` 取 `special`。按实际议程复制季度模板后删除"重机／重装季度工作报告""表彰"等无关骨架，**不强制季度报告结构，也不虚构事实**。
4. 所有任务均读取 [writing-and-layout.md](references/writing-and-layout.md)。
5. 用户另给当前会议模板时，先完整读取该模板并优先继承其有效版式；本Skill的历史规范只补充未规定事项。

## 二、执行完整工作流

### 1. 盘点素材与交付要求

区分每份素材的角色：

- **事实来源**：本次录音、逐字稿、议程、通报表、汇报PPT、表彰名单、领导讲话稿。
- **格式参考**：历史纪要、用户指定DOCX／PDF模板。
- **补充口径**：用户对录音起点、发言人身份、会议时间、缺省信息的明确说明。

未指定交付载体时，默认交付可编辑DOCX。

**DOCX 交付强制流程**：开始调用 `generate_minutes_docx.py`、或在用户提供的 DOCX 模板上直接编辑前，必须先完整读取内置 `word` Skill 的 `SKILL.md` 并按任务路由读取对应 workflow；Windows 环境还须读取内置 `word` Skill 自身的 `references/workflows/windows-compat.md`（该文件属于内置 word Skill，不在本目录复制）。本脚本仅用于无模板新建或统一复刻历史版式。

### 2. 完整获取全部有效内容

**录音输入**：

1. 先核验总时长、采样信息和可访问性，再调用当前环境适用的音频／会议转写能力；使用前读取对应Skill。
2. 长录音按连续时间段处理，保留每段起止时间、说话人和议题。分段必须首尾衔接并覆盖至文件末尾，不得只转写开头、抽样片段或智能摘要。
3. 回查低置信度、多人交叉、数字密集、项目型号密集和领导部署段落。区分有效发言、长时间静音、音乐和无意义背景声。
4. 从真实起点开始。若录音一开始就是某部门发言，就把该发言作为第一条有效内容，不虚构主持人开场或前置议程。

**逐字稿／文档／PDF输入**：

- 完整读取全部有效页面、段落、表格和备注，不以摘要替代原文。
- PDF同时提取正文并逐页检查视觉内容；扫描页、图片和表格中的信息不得遗漏。
- 多份材料冲突时保留差异并核对时间、对象和统计口径，不擅自拼接或混算。

### 3. 先建立来源覆盖台账，再起草

在临时工作区建立台账，每条有效来源至少记录：

| 字段 | 内容 |
|---|---|
| 来源ID／时间段 | 如 `S001`／`00:00:00-00:08:20` |
| 发言人／部门 | 无法确认时标待核，不猜测 |
| 议题与关键事实 | 项目、问题、原因、成果、案例 |
| 数字与行动项 | 指标、型号、金额、比例、责任人、节点、跟踪项 |
| 去向 | 纪要章节／段落，或排除原因 |
| 状态 | 已采用／已合并／已排除／待核 |

每个有效来源段必须映射到一个或多个正文段落，或以"纯重复、寒暄、无实质信息"等明确理由排除。**存在未映射的有效来源时，不得宣称纪要完整。** 合并相近内容时保留全部不可互相替代的信息。

台账中的每条来源必须落到 JSON `sources[]` 数组；实际录音有几段就登记几个 ID（模板默认 S001–S006 仅为演示，按实际来源段增删）。每个事实块（`item`／`body`／`paragraph`）必须通过 `source_ids` 或所属章节的 `default_source_ids` 追溯到已声明来源；脚本会强制校验。

### 4. 按实际会议组织正文

- 按真实议程和发言顺序搭建结构，使用对应会议类型的历史骨架补齐"应有但尚未检查"的部分，而不是补写不存在的内容。
- 某部门未发言、某领导未出席或无总经理回复时，不虚构相应段落，也不保留空标题（脚本会报错）。
- 月度例会重点呈现指标通报、部门问题与协调、分管安排、总经理逐部门部署及集团领导指示。
- 季度大会重点呈现周期经营报告、成果与不足、下一周期安排、表彰／专项活动、总裁部署和董事长讲话。
- 董事长专题授课或长篇讲话保留完整论证链、关键故事和管理启示，不压缩成空泛口号。

### 5. 书面化并控制详略

- 使用第三人称纪实表达，如"销售部提出""总经理要求""集团董事长强调"；直接引语仅在原文可核验时使用。
- 每段围绕一个中心意思，优先保留"事实／问题—原因—决定—责任—节点"。
- 删除口头重复、语气词、无信息铺垫和同义反复；合并同类项时不得丢失限定条件。
- 保留具体项目名、产品型号、数据单位、完成比例、排名、案例、奖惩、责任部门、协同关系、时间节点及明确提出的"（跟踪项）"。含"（跟踪项）"的条目在生成 DOCX 时该标记自动加粗。
- 工作部署必须来自会议，不根据历史高频主题自动添加"抢订单、回款、降本增效"等内容。
- 结尾动员、会议宣贯要求及领导归纳仅在实际出现时写入，篇幅与讲话重要性相匹配。

### 6. 通过五道质量门禁

1. **完整性**：录音时间轴闭合；所有部门、发言人、议程、有效议题均已在台账中处置，无未说明的中段缺口。
2. **事实性**：逐项核对姓名、职务、项目、型号、指标、金额、百分比、日期、排名、表彰名单和责任分工；当前材料与历史模板不串用。
3. **结构性**：会议类型、标题层级、部门顺序、领导讲话和结尾符合实际议程；编号连续且同级形式统一。
4. **精炼性**：无逐字稿式口语、无同义重复、无无故扩写；关键数字、案例、决策、行动项和主要意思未因压缩丢失。
5. **交付性**：无未解释的 `××`／TODO／待核占位，无来源覆盖遗漏；页眉、标识、水印、页码、字体和段落样式符合所选模板。

历史篇幅只能作为参考：月度例会通常约6—9页，季度／专项大会通常约11—16页；不得为凑页数增删实质内容。

## 三、修改类任务分支

- **补全纪要**：回到完整原始材料重建覆盖台账，定位缺失时间段、部门或议题后补入；不得凭现有纪要反向扩写。
- **精简纪要**：保留主要意思、发言人、关键指标、典型案例、部署要求、责任与节点；优先合并重复表述，不机械按字数比例砍段。
- **审校纪要**：分别检查遗漏、错听、数字冲突、归属错误、结构失衡、口语化和版式，不用单纯润色掩盖事实缺口。
- **套用新模板**：保留已核实的正文事实，仅调整样式与必要的结构映射，不借换版式改写会议结论。

## 四、使用JSON模板和DOCX脚本

模板：

- [monthly-template.json](assets/monthly-template.json)
- [quarterly-template.json](assets/quarterly-template.json)

先复制模板并填入本次会议内容。`sources` 按实际录音段数增删；`check_minutes_json.py` 会强制所有必需来源被正文 `source_ids`／章节 `default_source_ids` 引用，或在 `excluded_sources` 中说明排除原因。专项会议（`meeting_type: "special"`）复制季度模板后删除无关骨架即可，不强制季度报告结构。

首次使用前先安装依赖：

```text
pip install -r scripts/requirements.txt
```

校验与生成：

```text
python scripts/check_minutes_json.py <minutes.json>
python scripts/generate_minutes_docx.py <minutes.json> <output.docx>
```

- `<minutes.json>` 支持 UTF-8（含 BOM）编码，Windows 记事本/PowerShell 保存的文件可直接读取。
- 模板自身含占位符，仅测试模板时增加 `--allow-placeholders`；正式交付前不使用该豁免。
- 用户提供有效 DOCX 模板时优先在模板上编辑（按内置 word Skill 流程），本脚本用于无模板新建或统一复刻历史版式。
- 输出 DOCX 使用清晰中文名称，建议与"会议主题"一致，例如：`卫华集团2026年10月份重机公司例会纪要.docx`。
