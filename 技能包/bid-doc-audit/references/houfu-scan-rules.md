# PDF "后附"附件漏插检查规则（v1.5-Patch 升级）

> **v1.5 增量**：新增 4.5 节"财务报表、社保清单局部校验约束"，明确 5 页窗口内**只做轻量级特征线索匹配、不读取报表明细**；附件超出扫描窗口时统一标准提示。
>
> **v1.5-Patch 增量（2026-09-09 追加）**：新增第 7 节「5 页窗口内 OCR 局部处理建议」——明确本 skill 无内置 OCR 能力；如需读取图片内报表内容，仅对命中关键词对应的向后 5 页单独 OCR，不建议整本 PDF 全部 OCR。

## 用途

扫描本次上传的全部**报名 PDF**，识别"XXX：后附"标注后，向后最多扫描 **5 个页面** 验证对应附件是否真实插入。本规则**只输出线索与告警提示**，AI 不自动判定 ❌ 缺失项，全部写入独立工作表【人工资料完整性核对对照表】。

## 1. 关键词库（仅以下两类，全部基于冒号「：」+ "后附"，模糊也接受）

### 1.1 财务/审计类（共 6 个）

```
近三年财务报表：后附
近三年财务报表后附
财务报表：后附
审计报告：后附
XX年财务报表：后附       (XX/XX为任意年份数字)
XX-XX年审计报告：后附     (XX-XX为任意年度区间，如2022-2024)
```

匹配规则：

- 后附前面是 `财务报表` 或 `审计报告` 或 含 `财务`、`审计` 字样的短语；冒号（中英文 `:` 或 `：` 都接受）可选。
- 年份判定宽松：`XX` 至少 2 位数字、年度区间至少 `XXXX-XXXX`，正则如 `[\d]{2,4}`。

### 1.2 社保类（共 5 个）

```
社保清单：后附
社保证明：后附
社保缴纳记录：后附
社保参保证明：后附
社保：后附
```

匹配规则：

- 凡是 `社保`+ 可选 `清单 / 证明 / 缴纳记录 / 参保证明` + `：` + `后附`，全部命中。

## 2. 性能优化：5 页窗口

当在 PDF 第 N 页命中上述任一关键词时：

- **从当前页 N 起，仅向后最多扫描 5 个页面**（即 N+1, N+2, N+3, N+4, N+5）；
- **不读取 PDF 剩余全部页面**，控制处理耗时；
- 如果业务排版中，附件距离"后附"标注**确实超过 5 页**，由人工去 PDF 后续页码确认（本规则只对常见排版兜底）。

## 3. 检索线索

### 3.1 财务/审计类 → 附件必须含下列任一关键词

```
资产负债表
利润表
现金流量表
审计报告
会计师事务所
签章

```

### 3.2 社保类 → 附件必须含下列任一关键词


## 4. 三种结果处理（AI 不私自判定 ❌ 缺失，全部写入备注栏）

| # | 结果 | 备注栏文案 | 后续动作 |
|---|---|---|---|
| ① | ✅ 在向后 5 页窗口内检索到对应附件相关页面（命中线索关键词） | `PDF 第N页标注"XX后附"，向后扫描5页范围内已检索到对应附件相关页面，请人工确认内容是否完整有效。` | 不进 ❌，仅留线索 |
| ② | ⚠️ 在向后 5 页窗口内**未命中**线索关键词 | `⚠️【风险提醒】PDF 第N页写有"XXX：后附"，向后连续5页未检索到对应附件页面，极有可能忘记插入对应附件；若附件放在更靠后的位置，请人工手动继续往后翻PDF核查！` | 不进 ❌，仅发告警 |
| ③ | 📷 PDF 是扫描图片 PDF，`get_text()` 返回空字符串 | `【扫描PDF，无法识别"后附"文字，请人工自行检查是否插入对应附件】` | 整份 PDF 不进 ❌，归类人工复核 |
| ② 续 | ⚠️ 附件超出扫描窗口（`hit_page + 5 ≤ 总页数`） | `⚠️【附件超出扫描窗口】PDF 第N页标注"XXX：后附"，附件可能放置在第N+6页及之后，请人工继续翻阅PDF后续页面核对。` | 不进 ❌，仅发告警 |

## 4.5 v1.5 新增约束：财务报表、社保清单局部校验（禁止大批量解析报表）

### 4.5.1 触发条件

只有命中"XXX：后附"关键词锚点之后，才对该页向后最多 5 页开展附件线索校验。

**PDF 其余页面，不主动扫描、不解析财务报表、社保清单明细内容**——避免大批量读取报表，消耗算力与 token。

### 4.5.2 向后 5 页窗口内——只做轻量级特征线索匹配

#### 财务/审计类（不解读报表明细）

**只识别**：
- 报表类型关键词：`资产负债表` / `利润表` / `现金流量表` / `审计报告` / `财务报表` / `会计师事务所` / `审计意见`
- 招标要求对应的报表年份（如"近三年" → 识别`2023`/`2024`/`2025` 年份片段）

**不解读**：
- ❌ 报表内具体金额（数字、合计、合计行）
- ❌ 会计科目明细（货币资金、应收账款等）
- ❌ 财务比率、增长率、资产负债率
- ❌ 审计意见具体内容（保留意见 / 无保留意见 / 否定意见等）

#### 社保清单类（不逐行解析人员明细）

**只识别**：
- 社保类型关键词：`社保清单` / `社保参保证明` / `社保缴费记录` / `社保局` / `参保单位`
- 时间线索：`2023年` / `2024年` / `2025年` / `缴费月份` / `参保月份` / `XX月`

**不解析**：
- ❌ 逐行人员缴费明细（姓名 + 缴费基数 + 个人/单位部分）
- ❌ 参保人员身份证号
- ❌ 社保缴费金额
- ❌ 任何结构化的人员 → 月份 → 金额关联数据

### 4.5.3 识别结果落位

- **所有识别结果写入【人工资料完整性核对对照表】**——AI 不输出 ❌ 缺失判定。
- 主 sheet 仅以"📌 后附扫描线索"形式汇总出现该资料的提示，详细线索在独立 sheet 中查阅。

### 4.5.4 附件超出 5 页扫描窗口

- 当 `hit_page + 5 ≤ 总页数` 时（即附件可能放在第 N+6 页及之后），直接提示：
  > 「⚠️【附件超出扫描窗口】PDF 第N页标注'XXX：后附'，附件可能放置在第N+6页及之后，请人工继续翻阅PDF后续页面核对。」
- **不读取 PDF 后续全部页面**——本规则强制只扫 5 页，超出窗口视为人工兜底。
- 报告"建议"列填：「人工继续翻阅PDF后续页面（第N+6页及之后）核对附件是否插入」。

### 4.5.5 硬性禁令

1. **严禁逐行解析报表明细数据**——金额、科目、人员缴费明细、人员身份证号全部不得提取、不得展示在报告中。
2. **严禁扩大扫描范围**——即使怀疑附件在更后位置，也只扫 5 页，超出窗口交给人工。
3. **严禁把"5 页内未命中"判定为 ❌ 缺失**——只发告警，由人工决定。
4. **禁止引入第三方 OCR/图像识别**——报表若为图片型（如"财务报表：后附"后是扫描件），按"扫描 PDF 无法识别"处理，不调用 OCR 解析报表数字。

## 5. 强制约束

1. 本检查**只输出线索、告警提示**，**AI 不自动判定"缺失"，不生成 ❌ 缺失项**，**全部写进独立工作表【人工资料完整性核对对照表】的备注栏**，交由人工打开 PDF 确认真实情况。
2. 最多仅向后扫描 5 页，**不读取 PDF 剩余全部页面**。
3. 即使 5 页窗口内未命中，也**严禁**写出"该项缺失"或"该项违规"等 ❌ 措辞——只能写"⚠️ 风险提醒"或"未检索到"。
4. **不修改原有六大维度审核逻辑**，与人工核对表完全兼容。
5. **不读取 PDF 全部页面**已经通过 `scripts/scan_pdf_houfu.py` 中的 `page.get_text()` 按页号调用 + 仅扫后续 5 页实现。

## 6. 工作表字段定义

【人工资料完整性核对对照表】（Excel 单独 sheet）字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| 序号 | int | 1, 2, 3... |
| PDF 文件名 | str | 命中的报名 PDF 名称 |
| PDF 总页数 | int | 该份 PDF 的总页数（避免人工翻太远） |
| 命中关键词 | str | 财务/审计/社保类关键词原文 |
| 后附标注所在页 | int | 命中所在的页码（从 1 开始） |
| 5 页窗口扫描范围 | str | `第N+1页 ~ 第min(N+5, 总页数)页` |
| 结果分类 | enum | `✅ 检索到附件线索` / `⚠️ 风险提醒` / `📷 扫描PDF无法识别` |
| 命中附件线索 | str | 结果①时填入的附件关键词；结果②填"未命中"；结果③填空 |
| 备注 | str | 见 4 节备注栏文案 |
| 建议 | str | 仅结果②/③ 时填入："人工打开PDF自查第N+6页及之后" / "人工逐页检查PDF是否插入相应附件" |

## 6.5 【v1.5-Patch 新增】OCR 人工预处理——5 页窗口内 OCR 局部处理建议

> 本 skill 仅靠 PDF 文本层（`page.get_text()`）扫描"XXX：后附"标注与线索关键词。**没有内置图片 OCR 能力。** 当 5 页窗口内发现需要识读的图片型报表 / 社保清单时——必须由人工介入做局部 OCR 预处理。

### 6.5.1 5 页窗口内的两大典型场景

| 场景 | 说明 | 推荐处理 |
|---|---|---|
| 场景 ① | "XXX：后附"标注所在页本身是文本型（AI 能检索到"近三年财务报表：后附"），但后续 5 页内是扫描件/图片型报表 | 仅对**该 5 页内的图片型报表页**做局部 OCR |
| 场景 ② | "XXX：后附"标注所在页起全是扫描件（整 5 页 AI 都检索不到线索关键词） | 仅对该 5 页做局部 OCR，不向后扩窗 |

### 6.5.2 OCR 范围硬性约束

| 允许 | 严禁 |
|---|---|
| ✅ 仅对命中关键词的向后最多 5 页窗口内的图片型页面单独 OCR | ❌ 对整本 PDF 一次性 OCR（消耗算力/token，识别错误率高） |
| ✅ OCR 后生成可搜索 PDF（保留图片 + 叠加 OCR 文字层） | ❌ 让 AI 私自调用 PyMuPDF / Tesseract / 任何图像识别 API |
| ✅ OCR 仅用于辅助判定附件是否已插入（仍按路径 A/B 提示） | ❌ OCR 后解读报表内具体金额、科目明细、人员缴费明细 |

### 6.5.3 推荐 OCR 工具

- Adobe Acrobat DC：「扫描和 OCR」功能
- 福昕高级 PDF 编辑器：内置 OCR 引擎
- WPS Office：「PDF 转 Word」带 OCR 选项
- 在线 OCR（i2pdf.com、onlineocr.net）
- Windows OneNote：图片右键"复制图片中的文本"

### 6.5.4 OCR 完成后处理

1. OCR 完成后**另存为**新的可搜索 PDF（不要覆盖原 PDF）；
2. 重新提交本 skill 全流程审核；
3. AI 重新做 5 页窗口扫描，此时文本层可识别（按路径 A 处理）；
4. 即使 OCR 成功，**AI 仍只识别报表类型关键词与年份**，不解读金额、科目、人员明细（与 4.5 节硬性约束保持一致）。

### 6.5.5 OCR 介入的标准提示模板

> ⚠️【AI 无法识读图片内部文字】本 PDF 第N页标注"XXX：后附"，向后 5 页窗口内发现图片型报表/社保清单页面。**请人工仅对该 5 页单独 OCR**（推荐：Adobe Acrobat / 福昕 / WPS），生成可搜索 PDF 后再提交审核。**严禁 AI 对整本 PDF 全部 OCR；严禁 AI 私自调用 OCR 解析报表明细。**

### 6.5.6 硬性禁令

1. AI 不得调用任何 OCR / 图像识别 API 解析图片内容——本 skill 仅做文本层匹配。
2. 不得突破 5 页窗口——即使发现窗口内全是扫描件，也只能建议用户对该 5 页单独 OCR，禁止向后扩窗。
3. 不得把"OCR 失败"等同于"未提供资料"——OCR 是辅助工具，合规判定权在人工。
4. 不得把"5 页内未命中线索关键词"判定为 ❌ 缺失——只能写"⚠️ 风险提醒"或"未检索到"。
5. OCR 后即使文本层能识别出报表内容，也不得逐行解析金额、科目、人员明细——仍按 4.5.2 的轻量级特征线索匹配原则。
