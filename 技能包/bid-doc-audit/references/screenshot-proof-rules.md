# 图片/截图类资料特殊校验规则（v1.5 新增）

## 用途

针对以图片/截图形式提交的证明资料（PDF 内通常为扫描件或网页截图），PDF 文本层**无法读取图片内部文字**——若按普通文本类资料校验"PDF 文本层检索不到关键词→判定 ❌ 漏项"，会导致大量误报。本规则要求：

> **严禁仅凭 PDF 文本层检索不到，将截图类证明资料标记为 ❌ 报名漏项。**
> 一律归入 ⚠️ 人工必复核，由人工打开 PDF 复核图片内容。

## 3. 两种处理路径（强制执行）

### 3.1 路径 A：页面锚点关键词命中（资料页面实体已存在）

**触发条件**：PDF 文本层检索到第 2 节任意关键词。

**处理动作**：

1. **禁止判定 ❌ 报名漏项**；
2. 归入 ⚠️ 人工必复核；
3. 输出**强制标准提示**（人工必复核条目原文要求列）：

   > 「已检测到对应资料页面；页面内容为图片/截图，无法读取图片内部文字，请人工复核：资料主体单位是否为本单位、证书/截图时间、有效期是否满足招标要求」

4. 报告中保留指向具体页码（若能定位）。

### 3.2 路径 B：页面锚点关键词未命中（无法判断页面是否存在）

**触发条件**：PDF 文本层完全检索不到第 2 节任意关键词。

**处理动作**：

1. **禁止直接判定 ❌ 报名漏项**；
2. 归入 ⚠️ 人工必复核；
3. 输出**强制标准提示**（人工必复核条目原文要求列）：

   > 「未检索到资料页面锚点关键词，请人工打开 PDF 确认是否已附上该资料，资料为图片截图时文本层无法识别」

4. 提醒人工**可能 PDF 整本为扫描件**，文本提取完全为空，需人工逐页翻阅确认。

## 4. 硬性禁令

1. **严禁仅凭 PDF 文本层检索不到，将截图类证明资料标记为 ❌ 报名漏项**——任何"漏项"措辞（漏、缺失、未附、未提供）都不允许出现在此类资料的判定结果中。
2. **严禁调用 OCR、图像识别 API 解析截图内容**——本 skill 仅做文本层匹配，不引入图像识别；如需图片内容识别，由人工完成。
3. **严禁把"未检测到锚点"等同于"未提供资料"**——PDF 整本为扫描件时，所有截图类锚点都不会命中，但实际资料可能齐全。
4. **路径 B 必须保留完整标准提示**，不得简化或省略关键信息（"请人工复核"、"图片截图时文本层无法识别"等关键词必须保留）。

## 5. 报告落位规则

- 截图类资料命中/未命中统一进入主 sheet「合规审核报告」第三节 **「三、⚠️ 人工必复核项」** 中新增的 **📷 截图类资料人工必复核** 分类。
- 截图类资料的页面锚点识别线索（PDF 文件名、命中关键词、命中页码、是否截图 PDF）写入独立 sheet「人工资料完整性核对对照表」中新的分块（v1.5 升级）。
- 其它（如存在）图片类扫描件、合同扫描件等按"通用资质证书类"处理。

## 6. 与六大审核维度的关系

| 维度 | 截图类资料处理 |
|---|---|
| 漏项审核 | **不判定 ❌ 漏项**，统一归入 ⚠️ 人工必复核 |
| 错项审核 | 仍执行（图片内容若由人工发现与本项目不符，可标 ❌ 错项） |
| 有效期审核 | 由人工复核（图片 OCR 文字不能识别时） |
| 平台合规审核 | 同普通流程 |
| 格式审核 | 同普通流程 |
| 命名审核 | 同普通流程 |

## 8. 【v1.5-Patch 新增】OCR 人工预处理流程

> 本 skill 仅靠 PDF 文本层（`page.get_text()`）做关键词检索与命中判定。**没有内置图片 OCR 能力。** 当路径 A/B 都遇到"AI 文本层检索不到、但人工目视确认 PDF 中确有该截图页面"的情况时——不能由 AI 私自调用任何 OCR 工具对整本 PDF 执行识别，必须由人工介入做局部 OCR 预处理。

### 8.1 触发场景

| 场景 | 典型情况 | 必须采用方案 |
|---|---|---|
| 场景 A | PDF 含截图类页面（信用中国 / 国家企业信用信息公示网 / 中国执行信息公开网 等），AI 文本层检索不到锚点关键词 | 人工对**该截图所在页**做局部 OCR，再合并回 PDF 后重提 |
| 场景 B | 锚点关键词命中，但 AI 不能解读截图内部文字 | 仍按路径 A 输出标准提示；由人工目视复核图片内容 |
| 场景 C | PDF 整本为扫描件，`get_text()` 全为空 | 整本扫描件提示用户重新生成可搜索 PDF（或对整本做 OCR 后重提） |
| 场景 D | PDF 内"XXX：后附"的财务报表 / 社保清单落在图片型页面上，需读取报表细节 | **仅对后附向后 5 页窗口内的对应图片页做 OCR**，严禁对整本 PDF 全部 OCR |

### 8.2 推荐的本地 OCR 工具

- **Adobe Acrobat DC**：「扫描和 OCR」功能，识别率高，对中文支持好
- **福昕高级 PDF 编辑器**：内置 OCR 引擎，支持中文识别
- **WPS Office**：「PDF 转 Word」带 OCR 选项
- **百度网盘 PDF 转 Word**：在线 OCR 中文
- **在线 OCR**：i2pdf.com / onlineocr.net（适合单张截图）
- **Windows 自带 OneNote**：把 PDF 截图贴入 OneNote，右键「复制图片中的文本」

### 8.3 OCR 完成后处理流程

1. 用上述工具对该页生成可检索文本层（保持原图 + 叠加 OCR 文字层）；
2. 在 PDF 软件中**另存为**（不要直接保存覆盖原 PDF，避免破坏图片）；
3. 重新提交审核，重新跑本 skill 全流程；
4. AI 重新扫描文本层，此时应当能命中锚点关键词，路径 A 触发；如仍未命中，再继续按路径 B 输出标准提示。

### 8.4 严令禁止

| 禁止行为 | 后果 |
|---|---|
| AI 私自调用 PyMuPDF / Tesseract / 任何图像识别 API 解析截图 | 严禁——本 skill 不内置 OCR 能力 |
| AI 对整本 PDF 调用 OCR 一次性识别全部页面 | 严禁——消耗大量算力与 token，且表格/数字识别错误率高 |
| AI 把"未检测到锚点"等同于"未提供资料"，私自判定 ❌ 报名漏项 | 严禁——已在硬性规则 9 明确禁止 |
| AI 把截图类资料"OCR 失败"与"资料未提交"画等号 | 严禁——OCR 是辅助工具，最终合规判定权在人工 |

### 8.5 OCR 预处理标准提示（写进 ⚠️ 人工必复核段）

> ⚠️【AI 无法识读图片内部文字】本 PDF 包含截图类资料页面（具体页面：第N页）但文本层未检索到锚点关键词，可能是纯图片型 PDF。请人工对该页面做局部 OCR（推荐工具：Adobe Acrobat / 福昕 / WPS / 在线 OCR），生成可搜索文本层后合并回 PDF，再重新提交审核。**严禁 AI 私自判定为 ❌ 漏项；严禁 AI 对整本 PDF 全部 OCR。**

报告生成时，所有需 OCR 介入的资料页面统一写进上述标准提示，方便经办人按提示操作。
