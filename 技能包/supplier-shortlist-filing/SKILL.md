# 供应商入围填写资料（模块1：供应商入围资料库）

## Overview

收到甲方入围需求后，以本地 `E:\卫华供应商入围资料库` 下三份 Excel 台账为**唯一权威数据源**，完成：公司信息提取 → 资质/资料匹配（✅/⚠️/❌ 三色标记）→ 附件调取与重命名 → 按甲方输入格式输出成品文件 + 文件清单。所有输出均为副本，源资料库只读。

## 硬性全局规则（违反即失败）

1. **权威数据源**：公司信息、资质名称/编号/有效期、资料路径，一律以三份 Excel 台账为唯一依据。证书图片、PDF 仅作为附件原件用于调取，**禁止读取图片/PDF 内部内容、禁止 OCR、禁止解析业务字段**。
2. **禁止编造**：台账缺失、解析错乱、文件找不到 → 标记 `❌资料库缺失` 或 `⚠️需人工补充`，并明确告知用户；任何情况下不得编造资质、编号、有效期、公司信息。
3. **只读源库**：绝不修改、移动、删除 `E:\卫华供应商入围资料库` 内任何源文件；输出全部生成到工作区/输出目录副本。
4. **如实报告**：遇到无法实现的操作（如 PDF 无法内嵌进 Word）直接告知，不得虚构执行成功。
5. **强制复核提示**：所有成品文档末尾必须标注：
   `【本结果由AI生成，需人工复核、补充缺失资料，不做最终定稿，不可直接对外提交甲方】`
6. **模块边界（模块隔离）**：本模块（模块1）处理「需要填写公司信息、资质信息的调查表/入围文档」。若用户上传的是**资料要求/审核项清单类 Excel**（只需按清单归集对应文件，无需填写内容），且明确要求「执行【通用版-资料清单自动归集归档】模块」→ 归模块2（supplier-checklist-auto-archive）处理，本模块禁止触发其建文件夹、复制归集逻辑。

## 数据源（唯一权威）

| 台账 | 作用 | 关键结构 |
|---|---|---|
| `供方能力调查基础信息表.xlsx` | 公司基础信息 + 多类型明细数据 | **多工作表**（7 个 sheet，见下方专项规则） |
| `资质清单.xlsx` | 资质证书 | 类别、证书完整名称、证书编号、发证日期、有效期、持证人员、文件路径（相对资料库根目录）、状态 |
| `供应商入围资料清单.xlsx` | 佐证资料库 | 文件名、文件完整路径、文件后缀、大小、备注 |

### 供方能力调查基础信息表-多工作表专项读取规则（2026-09 追加）

该文件为**多工作表结构**，每个工作表有独立表头和用途，**必须逐工作表识别处理，禁止只认"项目-内容"两列、禁止跳过非键值表**。

| Sheet 名 | 类型标识 | 用途 |
|---|---|---|
| `供方能力调查基础信息` | `basic_info` | 两列"项目/字段名称-填写内容"键值对 → 填公司基础信息 |
| `主要客户信息` | `customers` | 客户名称/联系人/联系电话/产品名称/使用量/合同期限 → 客户列表 |
| `主要生产设备清单` | `production_eq` | 设备名称/规格型号/台套/制造厂家/出厂日期/单班产能/关键工序 → 设备列表 |
| `主要检验设备清单` | `inspection_eq` | 同上 → 检验设备列表 |
| `配套件供应商、外协件供应商` | `suppliers` | 设备/供应商名称/联系人/联系电话/供货能力 → 配套/外协供应商 |
| `设备年产量` | `annual_capacity` | 品名/规格/年产量 → 产能相关字段 |
| `财务信息` | `financial` | 指标名 × 2018-2025 年横向年度表 → 按（指标名+年度）匹配填入 |

**多工作表专项规则：**
1. **日期/数值自动识别**：脚本按 `cell.number_format` 判定日期格式（避免把"使用量 9656"、"注册资本 60000"误转为日期）。Sheet1 因 number_format 可能丢失，仍保留 `cell_str_legacy()` 自动转 `YYYY-MM-DD`。
2. **客户/设备/供应商填充**：识别甲方调查表对应表格（Row 0 或 Row 1 作为表头行），按表头逐列填写，从对应 sheet 按行顺序填入。
3. **设备年产量**：源表是"标签-值"交替结构（每行 6 列），已自动重组成 `[{序号, 品名, 规格, 年产量}, ...]`。
4. **配套供应商**：按表头填入甲方对应表格。
5. **缺失列处理**：源表缺某项设备 → 模板保留空行 + ⚠️需人工补充；禁止编造设备名称/型号/厂家。
6. **检验设备兜底**：甲方调查表没有"主要检验/检测设备清单"栏目 → 明确提示用户【该调查表未含"主要检验清单"栏目，是否需新增或补充】，不自行新建表格。
7. **财务信息**：按（指标名+年度）匹配；甲方要求"近三年/近X年"优先取最近可用年度，备注注明取数年度；数据源有但调查表无落点 → 末尾追加提示【数据源有该指标，调查表无落点】。
8. **多工作表解析产物**：`parse_ledgers.py` 默认输出 `ledgers_company_extended.json`（含全部 sheet 数据），用 `--skip-extended` 跳过。

**已知坑**（已内置容错，勿惊讶）：
- 《供应商入围资料清单》中「文件完整路径」存在缺分隔符的拼接错误（如 `...\供应商入围资料供应商入围资料\...`），脚本会**按文件名在资料库下递归搜索**自动修复；修复数会在校验报告中列出。
- 《供方能力调查基础信息表》中部分日期是 Excel 序列号（如成立日期 39120），脚本自动转为 `YYYY-MM-DD`。Sheet1 键值对因无 number_format，使用 `cell_str_legacy`，其内置**合理年份区间(1970–2100)守卫**：邮编 453400、缴纳社保 757、公司总人数 2600 等纯数字不会被误转成 3141-05-13 / 1902-01-26 / 1907-02-12 这类荒谬日期。

## 标准工作流程

每次业务任务按以下顺序执行：

### Step 1 — 解析台账（必做）

```bash
"$PY" "<skill目录>/scripts/parse_ledgers.py" --out <工作输出目录> --base "E:\卫华供应商入围资料库"
```

产物：
- `ledgers_company.json` — Sheet1 项目-内容键值对
- `ledgers_company_extended.json` — **全部 7 个 sheet 数据**（客户/生产设备/检验设备/供应商/设备年产量/财务+基础信息），多工作表专项规则
- `ledgers_qualifications.json` — 资质清单
- `ledgers_materials.json` — 资料清单（含实际文件定位结果）
- `ledgers_verify_report.md` — 校验报告（含多工作表解析摘要、路径修复数、缺失清单）

若台账缺失/解析为空 → 脚本会告警退出，此时**向用户告警**，禁止继续编造。加 `--skip-extended` 可仅产出基础 `ledgers_company.json`。

### Step 2 — 提取甲方需求

从甲方入围文档提取需求条目列表（每行一条），写入 `<工作目录>/req.txt`。提取原则：
- Word/PDF：逐条读取要求提供的资质/资料/信息字段（如"1、营业执照""质量管理体系认证"）；
- 图片/扫描件：可读取图片内容，但**不得从证书图片内提取业务字段**——需求条目以甲方文字要求为准；
- 若甲方文档本身无法可靠提取 → 询问用户或按用户提供清单为准。

### Step 3 — 需求匹配 + 附件收集

```bash
"$PY" "<skill目录>/scripts/match_requirement.py" --out <工作输出目录>/match \
    --req <工作目录>/req.txt --ledgers <工作输出目录> \
    --rename-pattern "<甲方要求的命名模板>"
```

- 匹配优先级：**资质清单 > 资料清单 > 公司信息字段**；
- `--rename-pattern` 支持占位符：`{原名}` `{无扩展名}` `{序号}` `{扩展名}`；不明确甲方命名规则时用默认 `{原名}`；
- 产物：`match_report.md`（✅/⚠️/❌ 三色表格）+ `match_result.json` + `附件副本/`（只读源文件的复制件）。
- 必须人工核对 `match_report.md`：⚠️ 多候选项需用户确认，❌ 缺失项需用户补充。

### Step 4 — 按输入格式组装成品

**前置：.doc 老格式转换（甲方是 .doc/.wps 时必做）**

python-docx 只能处理 .docx。甲方提供老式 `.doc` 时，先用 WPS/Word COM 转成 .docx 副本再继续（源文件不动）：

```bash
"$PY" "<skill目录>/scripts/convert_doc_to_docx.py" <甲方.doc> <工作输出目录>/转换副本.docx
```

- 优先 WPS（`KWPS.Application`），失败自动尝试 MS Word；两者都不可用时如实告知，请用户人工另存为 .docx；
- 转换产物为独立副本，源 .doc 只读。

**场景 A：甲方输入是 Word（文档内逐条列明所需资质）**

```bash
"$PY" "<skill目录>/scripts/build_filed_word.py" --docx <甲方Word> \
    --match <工作输出目录>/match/match_result.json --out <工作输出目录>/成品.docx
```

- 默认 `--inline`：在甲方文档对应条目段落下方插入「资质名称」加粗标题 + 证书原件；
  - jpg/png 等图片证书 → 直接插图（宽 5.5 英寸）；
  - PDF/docx/xlsx 等非图片 → 该处插入**超链接**指向副本（python-docx 无法内嵌 PDF 为附件对象，如实告知用户；若甲方必须内嵌附件对象，提示需人工在 Word 中插入）；
  - 文档中定位不到对应条目的 → 自动附到文档末尾并记录（符合"定位失败统一附末尾"规则）。
- 备选 `--appendix`：全部附件统一附在文档末尾，按甲方列举顺序，每项上方加资质名称标题。
- 产物：成品 Word 副本 + `word_insert_report.md`。

**场景 A2：甲方输入是 Word 表格型调查表（如「供应商能力调查表」）**

模板通常是「项目-内容」表格（公司基本情况）+「认证情况」表格（机构/编号/有效期）+ 末尾资质标题段。用 `fill_survey_template.py`（CLI 可传参，无需改脚本内路径；行→键映射在 map1 中维护，新模板需按实际模板调整 map1/cert_map/标题名）：

```bash
"$PY" "<skill目录>/scripts/fill_survey_template.py" \
    --src <甲方.docx> --out <工作目录>/成品.docx --ledgers <工作目录>   # 均为可选，默认回退旧路径
```

脚本内置处理（以 2026-09 实测模板为准）：
- 表1 公司基本情况：A列项目名 → 台账键映射填 B 列（合并单元格只写首个 cell）；
  - 联系电话←台账键`联系电话`、邮政编码←`邮政编码`（此前曾被日期序列号误转，已修复守卫后直接可填）；
  - 年度销售总额←台账键`上年度销售额`（若存在），并在填充报告中提示其与财务 Sheet 营业收入/营业成本的口径差异，禁止拿营业成本替代；
  - 员工情况→员工总数/管理人员/质检/本科以上学历组合文本，技术人员/缴纳社保等纯数字键因台账存在双记录疑点，以「口径待人工核对」备注而非直接并入正文；
- 表2 认证情况：把台账的「发证单位/证书编号/有效期」追加到单元格已有标签（认证机构：/证书编号：/有 效 期：）之后；
- 「企业简介/质量控制/售后」等正文标题段：填充台账对应键值；
- 末尾资质标题段（营业执照/特种设备生产许可证/质量管理体系证书…）：在对应标题下插图；认证表中其余资质按甲方顺序附文档末尾（标题+图）；
- 台账无值/值异常 → 单元格留空并记 ⚠️，绝不编造；
- 文档末尾强制加 AI 复核提示（若已有则不重复）。
- 产物：成品 docx + 控制台填充报告（fill_report）。

**场景 A3：甲方输入是 Word 表格型调查表（含客户/设备/供应商/财务等多工作表对应表格）**

Step 2+A2 已处理"项目-内容键值对"型表，但当甲方调查表还有"主要客户信息""主要生产设备清单""主要检验设备清单""配套件/外协件供应商""设备年产量""财务信息"等明细表时，用 `fill_multi_sheet_tables.py`（多工作表专项规则）：

```bash
"$PY" "<skill目录>/scripts/fill_multi_sheet_tables.py" \
    --template <甲方Word .docx> \
    --extended <工作目录>/ledgers_company_extended.json \
    --out <工作目录>/成品.docx
```

脚本内置处理：
- **自动识别表类型**：扫描 Word 所有表格，按表头关键字（"客户名称""主要生产设备""设备年产量""财务"等）自动分类为 `customers / production_eq / inspection_eq / suppliers / annual_capacity / financial`；
- **支持合并标题行**：若 Row 0 是合并的标题（如"主要生产设备清单"占满 12 列），自动用 Row 1 作为真实列头；
- **逐列映射填入**：源表头 → 模板表头双向匹配（含模糊包含），按设备名称/规格型号/台套/制造厂家/出厂日期/单班产能/关键工序 等字段填充；
- **合并单元格处理**：每个合并 cell 只写一次，不重复；
- **财务信息特殊处理**：按 (指标名, 年度) 匹配填入对应格子；模板行多出 → 留空 + ⚠️；源表未落点 → 文档末尾追加提示；
- **缺失列处理**：源表缺某项设备 → 模板保留空行 + ⚠️需人工补充；禁止编造设备名称/型号/厂家；
- **检验设备兜底**：甲方调查表没有"主要检验/检测设备清单"栏目 → 明确提示用户【该调查表未含"主要检验清单"栏目，是否需新增或补充】，不自行新建表格；
- **输出**：成品 docx + `multi_sheet_fill_report.md`（逐表填充说明 + ⚠️ 清单 + 数据源有但模板无落点的财务指标）。
- 文档末尾强制加 AI 复核提示。

**场景 B：甲方输入是 Excel（需填公司信息）**

```bash
"$PY" "<skill目录>/scripts/fill_company_info.py" --template <甲方Excel模板> \
    --out <工作输出目录>/填写后的表格.xlsx --ledgers <工作输出目录>
```

- 遍历模板单元格，与台账键名做包含匹配，命中后填右侧空单元格（其次下方）；

**场景 B2：甲方输入是 Excel 横向汇总宽表（如「投标单位资格预审汇总表」）**

单 sheet、1 条数据行、20+ 横向列，部分列（序号/名称/注册时间/资本/法人/规模）已预填，需补齐剩余列。用 `fill_bid_qual_summary.py`（坐标映射按实测模板写死，新表需按表头微调）:

```bash
"$PY" "<skill目录>/scripts/fill_bid_qual_summary.py" --template <甲方.xlsx> \
    --out <工作输出目录>/成品.xlsx --ledgers <工作输出目录>
```

- 坐标映射（2026-09 实测模板）：H企业简介←简介 / I官网←网址 / J邮箱←邮箱号 / K地址←实际经营地址 / S厂房面积←生产/服务场地面积(85万平方米→850000) / Z资质证书←《资质清单.xlsx》证书完整名称每行一条(排除银行开户/税务)；
- 长文本单元格设 wrap_text+top 对齐，并调大该行行高（150）保证多行可见；
- 已预填列一律不覆盖（含 W 列业绩占位符，按约定不读明细台账 → 保留并标 ⚠️）；
- 财务数值列（营业收入/净利润率/资产负债率/人均营收）台账无 → 留空 ⚠️，不读取财务报表 PDF 内容；
- 人数类：日期守卫（1970-2100）修复后，公司总人数 2600、缴纳社保 757 等纯数字键**已可正常读取填入**（不再误转日期、不再留空）；简介口径（"员工2600多人"）仍不作正式数据。

**场景 B3：甲方输入是 Excel 考核/评鉴表单（评鉴表 + 附件 sheet 型）**

结构特征：一个「03-供应商评鉴表--资料评鉴」类主表（多行键值+合并单元格，含开发类别勾选、厂商概况、客户群/设备文本格）+ 若干附件 sheet（营业执照/社保证明/合作合同/房产证等，每个 sheet 放一类原件图）。用 `fill_assessment_form.py`（CLI 通用版，2026-09 从硬编码改造而来）:

```bash
"$PY" "<skill目录>/scripts/fill_assessment_form.py" --src <甲方模板.xlsx> \
    --out <工作输出目录>/成品.xlsx --ledgers-dir <parse_ledgers输出目录>
```

- 主表填值：C4开发类别/C5全称/C6地址/C7法人+F7联络人/C8电话+F8传真、D10成立时间/G10员工人数、D11上年度销售额/G11注册资本/实缴、D12场地面积/G12库房、D13产品+经营范围、D14客户群(前12家+总数)、D15主要设备(前8类+总数)；写值自动落合并区左上角；

- 客户群/生产设备文本格数据来自 `ledgers_company_extended.json` 多工作表（《供方能力调查基础信息表》子表），历史曾因未识别多工作表而留空，现按规则填充；
- 附件 sheet：营业执照插资质清单解析出的原件图；合同/房产证类 PDF → pymupdf 转图放置（**仅格式转换，不解析内容**）；社保证明等台账无 → 写 ❌缺失说明到 A1，**绝不编造**；
- 末尾 AI 复核提示防重复追加（已存在则跳过）；
- 产物：成品 xlsx + `assessment_fill_report.md`。

**场景 B4：甲方输入是 Word 单大表调查表（如「供应商基本信息调查表」）**

结构特征：单一表格 35 行 × 7 列覆盖 5 个小节（§1 供应商基本情况 / §2 体系认证 / §3 产品基本信息 / §4 证实性材料 / §5 自评清单）。**§3 含嵌套子表**；**§5 是 25 项评价清单**（A 法人资格 / B 专业技术资质 / C 体系资格 / D 经营信誉），每项需勾选「合格/不合格」+「是否通用」。用 `fill_basic_info_survey.py`（CLI 通用版，2026-09 实测）：

```bash
"$PY" "<skill目录>/scripts/fill_basic_info_survey.py" --src <甲方docx> \
    --out <工作输出目录>/成品.docx --ledgers-dir <parse_ledgers输出目录>
```

- §1 基本情况：17 字段标签 + 待填区全在 R02 单 tc 内 → 用 `OxmlElement('w:p')` 在 tc 尾部追加"字段名：值"段落（CT_Tc 没有 add_paragraph，需走原生 OxmlElement API）；
- §2 体系认证：按《资质清单》找 ISO9001/ISO14001/OHSAS 等已通过证书，在 R04 tc 末尾追加摘要（**模板内 □ 勾选项不自动改**，留人工在 WPS/Word 中勾选 ■）；
- §3 产品信息：定位 R05 行内的 `<w:tbl>` 嵌套子表，按行填入执行标准/技术人员/主要工装设备等 10 项可覆盖内容；具体技术指标/试验报告等需人工细化；
- §4 证实性材料：识别已具备的 □1/□8/□12 等，提示人工勾选；
- **§5 自评清单（R09-R35 共 25 项）**：**禁止自动勾选**——必须由业务人员判断「合格/不合格」，AI 代决风险高；
- 末尾 AI 复核提示明确标注「需人工补充缺失资料及自评清单勾选」；
- 产物：成品 docx + `basic_info_fill_report.md`。

**场景 B5：甲方输入是 Word 准入预审/评审表（甲方评审供方用，含评价结果列）**

与"供方填基础资料"型模板不同，本类是**甲方对供方做准入评审**的表（含「评价结果」列），填法原则：
- 「实际情况简要描述」列 → 填台账可核实依据（短文本 + 证书号/有效期）；
- 「评价结果」列 → 台账可确定项自动填 ■ 满足要求 / ■ 不满足要求；不确定项填 □ 待人工判定（**不擅自评判商业信誉/特定关系人/廉洁从业**等需外部核实的项）；
- R23-R25 预审/审核/批准意见 → **完全留空**（内部审批流程，绝不由 AI 介入）；
- 评价人/岗位/签字栏 → 留空；
- R03 □ → ■ 勾选（按台账可判断的供应商类型）。

模板结构识别要点（gridSpan 而非 vMerge）：
```
[0]序号 gs=1 [1]评价内容 gs=1 [2]评价标准 gs=2
[3]实际情况简要描述 gs=2 [4]评价结果 gs=2 [5]备注 gs=1
```

脚本：`fill_baoji_preassessment.py`（CLI 版，2026-09 实测适用宝鸡石机预审表）。

用法：
```bash
"$PY" fill_baoji_preassessment.py --src <甲方docx> --out <成品.docx> --ledgers-dir <工作目录>
```

产物：成品 docx + 文件清单.md。

### Step 5 — 输出文件清单（必做）

无论哪种输出，必须同时整理一份**文件清单**（建议 `文件清单.md`），包含：甲方需求条目、匹配标记、调用的源文件、输出副本文件名/路径、缺失项、待人工补充项。

## 资料库更新维护

用户可在 `E:\卫华供应商入围资料库` 下新增/更新台账与资料文件；每次业务任务都**重新执行 Step 1 解析**，自动使用最新版本，无需重新上传。台账结构变化（列名改动）导致解析失败时，如实告警并请用户确认新结构。

## 安全与合规

1. 只读源库，输出全为副本（输出目录建议放在工作区，如 `C:\卫华投标工作区\<会话目录>` 下）；
2. 匹配不确定 → ❌/⚠️ 标记，绝不编造；
3. 无法实现 → 直接告知；
4. 所有交付物标注 AI 生成需人工复核提示，且最终必须由用户对照原件复核。
