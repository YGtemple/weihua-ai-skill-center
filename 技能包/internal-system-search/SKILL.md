# 内部系统信息查询整理（internal-system-search）

## Overview

把「进内部系统 → 逐模块检索 → 翻页取全量 → 清洗核对 → 台账化输出」串成一条可复用流水线。输入是一个企业名称（或项目名、供应商名、证书编号），输出是带来源标注、可直接进投标台账的结构化条目。

一句话原则：**只读取、不写入；只搬运、不编造；取不到的标空并提示，不猜。**

## 何时使用

- 用户给出一个单位/项目名称，要求在内部业务系统里查"这个单位在我们系统里都有什么记录"。
- 投标前要拉某供应商的历史合作痕迹：中过标没、签过合同没、来考察过没、报过价没。
- 需要把散在 7 个模块里的记录，整理成一条条能贴进台账的规范句子。
- 用户提到 search / 内部查询 / 信息检索 / 查单位 / 查业绩 / 查证书。

不适用：需要新增、修改、审批、导出系统数据的请求（本技能严格只读）；纯外部公开信息检索（用 WebSearch）。

## 输入（缺项先问，不要猜）

| 参数 | 说明 | 默认 |
|---|---|---|
| 系统地址 | 内部系统 URL，或本地原型 HTML 路径 | 无，必填 |
| 检索关键词 | 企业名称/项目名/供应商名，支持多关键词逐个跑 | 无，必填 |
| 检索字段 | 单位名称、订货单位、招标单位（有则全填，命中即算） | 三者全用 |
| 目标模块 | 需要查哪些模块 | 全部 7 个 |
| 输出用途 | 投标台账 / 业绩表 / 客户画像 | 投标台账 |

## 硬性规则（违反即失败）

1. **只读**：只允许「输入关键词 → 点查询 → 翻页 → 读表格」。禁止点新增/修改/复制/删除/上传附件/保存；误触打开表单弹窗要立刻关闭，不点保存。
2. **遇阻即停**：出现登录页、验证码、滑块、二次确认弹窗、权限不足提示，立即停止并明确告知人工接管，不尝试绕过、不重复试错。
3. **全量**：每个模块必须翻到最后一页；只取首页即视为失败。系统显示的总条数与实际读取条数要能对上。
4. **不编造**：任何字段取不到就写「—」或「未查到」，绝不根据常识补全金额、编号、日期、人名。
5. **留痕**：每条结果必须带【来源：XX模块】，跨模块合并时保留全部来源。
6. **单位换算**：金额一律换算为万元并保留 2 位小数，原始单位在括号内注明（如 `0.13万元（1324.05元）`）；无法判断原单位时先按系统列头单位处理，列头不明则标注「单位待核」。

## 执行流程

### 第 1 步 · 准备浏览器

1. 优先用 Edge。
2. `http(s)` 地址：直接导航。
3. **本地 `file://` 页面无法被浏览器扩展脚本控制**。处理方式：在文件所在目录起本地静态服务
   `python -m http.server 8873 --bind 127.0.0.1`，再导航到 `http://127.0.0.1:8873/<文件名>`。
   页面内容与本地文件完全一致，收尾时关闭该服务并说明。
4. 页面加载后先截一张图确认：当前是哪个模块、筛选区字段有哪些、表格列有哪些。

### 第 2 步 · 逐模块检索

按模块清单顺序执行，每个模块固定动作：

1. 切到该模块（顶部标签页 / 左侧导航）。
2. 在【单位名称】【订货单位】【招标单位】中能用的那个框填入关键词（模糊匹配即可，不要加引号、不要带「有限公司」以外的后缀）。
3. 点「查询」。
4. 读结果条数与表格内容；有多页则逐页读取，直到最后一页。
5. 记录：命中条数、关键字段值、是否空结果。

推荐模块顺序（按业务重要性）：委托信息 → 标书查看 → 合同列表 → 盖章信息 → 外部报价 → 技术支持单管理 → 接待列表。

各模块取哪些字段（字段名以系统实际列头为准，缺列则跳过）：

| 模块 | 必取字段 | 用途 |
|---|---|---|
| 委托信息 | 查询日期、代销商、项目类型、单位名称、查询情况、是否完成 | 线索与意向 |
| 外部报价 | 日期、业务员姓名、单位名称、报价总额 | 报价痕迹 |
| 盖章信息 | 签订日期、代销商、单位名称、合同类型、金额 | 合同签订 |
| 合同列表 | 下发时间、内部代销商、订货单位、类型、合同外部金额 | 业绩台账核心 |
| 技术支持单管理 | 填表时间、代销商、单位名称、报价状态 | 技术支持量 |
| 接待列表 | 来访日期、代销商、单位名称、考察类型 | 客户关系 |
| 标书查看 | 开标时间、业务员、招标单位、项目名称、投标结果 | 投标记录 |

### 第 3 步 · 委托信息特判（优先级最高）

对【委托信息】的每条命中记录单独判断 `项目类型`：

- **= 购买标书**：本条委托**不收录**（跳过委托本身）。改到【标书查看】用「单位名称 + 项目名称」做二次匹配。
  - 匹配成功 → 只采集【标书查看】里那条项目的信息，来源标注为标书查看。
  - 匹配不到 → 输出一条备注：`【备注】委托信息模块查到购买标书委托，标书查看模块未找到对应项目`。
- **≠ 购买标书**（平台报价 / 项目登记 / 供应商调查表 / 甲方直采 等）：正常采集委托信息。
- 【标书查看】里独立检索到、不是由购买标书委托联动出来的记录：正常采集。

### 第 4 步 · 清洗与核对

逐条过一遍：

1. **日期**：统一 `YYYY-MM-DD`；`2026-11-1`、`2026/11/01`、`2026年11月1日` 都归一到 `2026-11-01`；带时分秒的只留日期，除非模板明确要时间。
2. **金额**：见硬性规则 6。
3. **空值**：`—`、`-`、`/`、空串统一写「—」；投标结果为空按第 6 步规则推导。
4. **去重**：同一模块内，单位名称 + 金额 + 日期三项相同视为重复，保留一条；跨模块不去重（不同模块代表不同业务环节，都有价值）。
5. **主体核对**：同一单位在多个模块里的名称写法不一致（带/不带「有限公司」、简称、曾用名）时，以合同列表的订货单位写法为准，其余归一，并在备注里说明归一动作。
6. **交叉校验**：合同金额与盖章金额差异超过 5% 要标注「金额待核」；委托说"已签合同"但合同列表无记录要标注「合同记录缺失」。

### 第 5 步 · 结构化输出

默认输出顺序 = 模块顺序，每条带序号与来源，**每句以「。」结尾**，不写多余解释。模板：

```
1.【来源：委托信息模块】查询时间 + 代销商 + 项目类型 + 单位名称，查询情况：XXX。
2.【来源：外部报价模块】日期 + 业务员姓名 + 盖章 + 单位名称 + 报价单。
3.【来源：盖章信息模块】签订日期 + 代销商 + 签订 + 单位名称 + 合同类型 + 金额（万元）。
4.【来源：合同列表模块】下发时间（YYYY-MM-DD）+ 内部代销商 + 签订 + 订货单位 + 类型（起重机→写"整机"）+ 合同外部金额（万元）。
5.【来源：技术支持单管理模块】填表时间 + 代销商 + 询价 + 单位名称。
6.【来源：接待列表模块】来访时间 + 代销商 + 带 + 单位名称 + 客户来考察。
7.【来源：标书查看模块】开标时间 + 业务员 + 投标 + 招标单位（+项目名称）+ ：投标结果。
```

规则细节：

- 标书查看的**「招标编码」行及其信息不汇总**。
- 投标结果为空 → 写「结果未出」；开标时间 > 当天 → 写「未开标」；有值（中标/未中标/落标）→ 原样输出。
- 无命中的模块，末尾统一标注：`XX模块无相关检索记录`。
- 输出开头一句话交代检索词与检索字段，结尾一句话交代：命中总数、空模块、以及是否触发过购买标书联动。

### 第 6 步 · 台账化（用户要"能贴台账"时）

在上述文本后追加一段制表数据（Markdown 表格，列固定），方便直接粘进投标台账：

| 序号 | 单位名称 | 业务环节 | 日期 | 金额(万元) | 项目/合同编号 | 关联人员 | 投标结果 | 来源模块 |

`业务环节` 取值：委托线索 / 报价 / 合同签订 / 技术支持 / 客户考察 / 投标。

## 浏览器自动化技术要点（实操经验）

- 元素操作优先用 DOM 快照按 `aria-label` 定位输入框和「查询」按钮，比坐标点击稳。
- DOM 快照是**快照级**的：每次输入/点击后页面重渲染，旧 node_id 会失效，需重新取快照再点。
- 顶部标签页、左侧导航是 `div`，不在可访问性快照里，只能用坐标点击；截图与点击坐标系可能不一致（实测存在约 x×0.765、y×0.93 的换算差异），先用一次无害点击（点当前已激活的标签页）校准，再批量点。
- 坐标点击前后都截图校验，点到「新增/修改」类按钮要立即按 Esc 关闭抽屉，绝不点保存。
- 全程不要触发「Excel导出」，避免产生下载文件与写操作痕迹。

## 质量自检（交付前逐条过）

1. 7 个模块都进过、都点过查询了吗？
2. 有分页的模块翻到底了吗？总条数与读取条数对得上吗？
3. 购买标书类委托按特判处理了吗？备注写了吗？
4. 每条都有【来源：XX模块】吗？
5. 金额都换算成万元并注明原值了吗？
6. 日期都规范成 YYYY-MM-DD 了吗？
7. 有没有出现系统里不存在的字段值（编造）？
8. 空模块标注了吗？
9. 每句是否都以「。」结尾？

## 异常处理

| 情况 | 处理 |
|---|---|
| 登录页 / 验证码 / 滑块 | 立即停止，说明卡在哪一步，请人工完成后继续 |
| 查询无结果 | 换检索字段重试一次（单位名称→订货单位→招标单位），仍无则记「无记录」 |
| 关键词命中过多（>200 条） | 先用单位名称全称精确化；仍过多则按时间倒序取近 2 年，并在输出里说明截取口径 |
| 页面结构改版、列头对不上 | 停止解析，把实际列头截图/列出，请用户确认字段映射后再继续 |
| 系统响应超时 | 刷新一次重试；连续两次失败即停止并报告，不反复刷 |
