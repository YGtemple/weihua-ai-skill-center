# 招标平台自动注册填报

## 用途

在各类招标平台、采购平台、供应链门户上完成供应商注册与入库填报：读取本地供应商资料库，把公司基础信息、开票信息、联系人信息填进网页表单，把资质证件按清单上传并填写有效期，最后输出执行报告供人工核对。默认服务对象为起重机械制造类企业（特种设备生产许可、起重设备安装资质、体系证书等），资料口径按资料库实际结构执行。

## 触发场景

- 用户给出注册网址并要求"注册/填报/入库"：`register`、招标注册、供应商入库、注册填报、平台入库资料上传
- 用户要求"按资料库填某平台的供应商信息表"
- 用户要求整理业绩、证书、财务资料用于平台入库

## 固定资料源

默认资料库根目录：`E:\卫华供应商入围资料库`。若用户另行指定路径，以用户指定为准。

同时读取三个核心文件，缺一不可：

| 文件 | 用途 |
|---|---|
| `供方能力调查基础信息表.xlsx` | 公司基础信息、法人、联系人、开户行账号、证书编号与有效期 |
| `供应商入围资料清单.xlsx` | 全部可上传资料的完整路径（文件名/路径/后缀/大小/备注） |
| `资质清单.xlsx` | 证件类资质的主清单（类别/证书完整名称/资料库内相对路径/状态） |

**匹配优先级：资质清单为主，供应商入围资料清单为辅。两者冲突时以资质清单为准；两者互补，合并去重后得到最终待上传集合。**

先执行 `scripts/export_supplier_data.py` 生成结构化缓存（含文件存在性校验与路径补正），再据此填表。

## 执行前置

1. 由用户提供目标注册网址。内部 http 站点出现证书/不安全提示时，直接继续操作，不中断流程。
2. 浏览器固定使用 Edge，交由 WorkBuddy 接管控制（内置浏览器仅在用户同意时使用）。
3. 页面需要登录时，暂停并向用户索取账号密码，不猜测、不尝试弱口令。
4. 全程只读本地资料库，**不新增、不修改任何 Excel 文件**。

## 执行流程（严格顺序）

1. 确认目标网址与登录方式。
2. 打开 Edge 访问该网址，进入供应商注册/入库填报页。
3. 读取 `供方能力调查基础信息表.xlsx`，缓存全部基础信息。该表含多个子表（基础信息、主要客户、生产设备、检验设备、配套件供应商），**填表只用基础信息子表**，其余子表仅作业绩与能力参考。
4. 读取 `资质清单.xlsx` 与 `供应商入围资料清单.xlsx`，按优先级合并去重，生成待上传集合（文件路径 + 有效期 + 备注）。
5. 逐项识别页面输入框，按"字段匹配规则"填入。
6. 遍历上传控件，按集合匹配文件逐个上传，并同步填写对应有效期。
7. 全部完成后暂停，输出执行汇总报告。
8. 等待用户确认后再提交，**永不自动点击提交**。

## 字段匹配规则

按语义匹配，不要求表头逐字一致。完整同义词表见 `references/field-mapping.md`。核心映射：

| 页面字段 | 取值来源（基础信息表） |
|---|---|
| 单位名称 / 供方名称 / 企业名称 / 投标人名称 | 公司全称 |
| 统一社会信用代码 / 税号 / 纳税人识别号 | 统一社会信用代码 |
| 法人 / 法定代表人 | 法定代表人 |
| 注册地址 / 公司地址 | 注册地址 |
| 联系人 / 项目对接人 | 项目对接联系人 |
| 联系电话 / 手机 | 联系电话 |
| 电子邮箱 / 邮箱 | 联系邮箱 |
| 开票名称 / 户名 | 公司全称（与单位名称一致） |
| 开户行 / 开户银行 | 开户银行 |
| 银行账号 / 账号 | 账号 |
| 企业类型 / 企业性质 | 企业性质，按页面选项归类（如"其他有限责任公司"→"有限责任公司"） |
| 注册资本 / 成立日期 / 经营范围 / 员工人数 | 同名字段 |

补充规则：

- 页面出现"授权人/被授权人/授权代表"时，先查两份清单中的授权信息；没有则**停下来向用户索取**，不自行编造。
- 页面要求"开户行行号"时使用基础信息表"行号"字段；无该字段时标记人工核对。
- 同一信息存在多个来源且不一致时（如"联系电话"与"项目负责人电话"），默认取与联系人同段的电话口径，并在报告中标注差异供用户确认。
- 字段名与表格表头语义拿不准时，标记【人工核对】并留空，不猜测填充。

## 文件上传规则

1. 只上传两份清单里列明的资料。清单没有的文件，即使资料库中存在也不上传（典型：厂区图片、宣传册）。
2. 清单标注【暂缺】或清单内找不到实际文件的资质，**停止上传该项**，在日志中标注 `【资质缺失：XXX】`，不上传空文件、不用相近文件顶替。
3. 页面控件与清单条目按语义匹配：营业执照→营业执照、信用截图→供应商资质与信用类截图、体系证书→ISO9001/14001/45001、财务报表→近三年财务报表（财务审计报告）、业绩合同→近三年业绩合同、承诺书→清单内承诺/声明类文件。
4. 一个控件对应多份同类文件时（如 6 张信用截图但页面只有一个"信用截图"控件），上传语义最贴近的一张，其余在报告中列出未上传项。
5. 清单记录路径失效时按三级补正，并记录补正方式（不修改 Excel）：
   1) 同目录按文件名找 → `same_dir_name`
   2) 全库按同名文件找（资料库被重组移动）→ `moved_same_name`
   3) 去空白标点后模糊唯一匹配 → `fuzzy_unique`；多条命中则标 `fuzzy_ambiguous`，列为候选由人工确认
   三级都没命中才判定缺失。
6. 补正后扩展名与清单登记不一致时（典型：资料库把 docx/xlsx/jpg 统一转成了 pdf），先看页面 `accept`：允许该格式才上传，不允许则**不硬传**，标 `【格式不符：需人工转换】`，在报告中列出原格式与现格式。
7. 上传前核对文件大小。清单登记大小与磁盘实际大小差异过大（如登记 5MB 实际 10KB），视为可疑文件，上传但标注【文件疑似异常，请人工确认】。

## 有效期填写口径

1. 页面有"有效期/证书有效期至"输入框时，先看资质清单备注，其次用基础信息表的证书有效期。
2. 若资质清单本身**没有有效期列**（仅"状态：有效"），有效期一律从基础信息表取：质量/环境/职业健康三体系、建筑业企业资质、特种设备生产许可证、安全生产许可证均有起止日期，取**截止日期**。
3. 清单与基础信息表都没有到期日的资质（常见：营业执照、高新技术企业证书、开户许可、一般纳税人证明、信用截图、现场照片），按顺序处理：
   - 页面为文本输入框 → 填"长期"；清单备注有特殊要求时按备注。
   - 页面为 `date` 控件（不接受文本）→ **留空**，在报告"待人工核对"中列明，等用户给准确日期后补填。
4. 日期统一 `YYYY-MM-DD` 格式。

## 浏览器操作要点

- 用 `mcp__browser__*` 系列工具；Edge 通过扩展接入。先 `browsers_list` 确认实例，再 `tabs_new` 或 `tabs_claim`。
- 优先 DOM 定位（`dom_cua_get_visible_dom` + `dom_cua_click`）。DOM 节点标识仅在当前快照有效，页面变化后必须重新获取。
- 输入框聚焦后再输入；`dom_cua_type` 偶尔不落到目标框，输入后**必须截图复核**，为空则用坐标点击重新聚焦再输入。
- `dom_cua_get_visible_dom` 返回的 `value` 属性可能不反映真实输入值，不要仅凭它判断是否填成功；以截图或页面回显为准。
- `<select>` 下拉：点击后用 `ArrowDown`/`Enter` 选择。键盘操作可能在未聚焦时滚动整页，选择后必须截图确认命中项。
- `<input type=date>` **不接受** `insertText` 与模拟键盘输入，键盘填入只停留在编辑态、不提交 value。只能由页面脚本用原生 value setter 加 `input`/`change` 事件赋值；页面不可注入时留空并列入人工核对。
- `<input type=file>` 无法用键鼠驱动 Windows 文件选择框。可行做法：本地起 http 服务承载页面，由页面脚本 `fetch` 本地文件并用 `DataTransfer` 注入 file 控件（仍使用清单中的真实文件）。该做法必须在报告中向用户说明。
- 页面 `alert()` 会阻塞自动化，可在承载层把 `alert` 替换为页内提示条。
- 页面为本地 HTML、没有真实域名时，用本地 http 服务承载原文件（不修改原文件），并告知用户端口与关闭方式。

## 硬约束

1. 只读本地 Excel，不写回、不新建表。
2. 找不到表格或文件立即停止，输出 `【文件不存在：xxx路径】`，禁止编造内容。
3. 不上传清单以外的文件。
4. 短信验证码、图形验证码、电子签章等自动化无法完成的步骤留给人工。
5. 不自动点击"提交/保存/确认入库"，一律等用户指令。

## 执行汇总报告

按 `references/report-template.md` 输出，必须含四段：已填写字段清单、已上传资质+有效期、缺失资质清单、待人工核对项。报告要能独立阅读——用户不看中间过程也能知道填了什么、传了什么、缺什么、下一步做什么。

## 配套脚本

`scripts/export_supplier_data.py`：读取三个核心表并输出结构化 JSON 缓存。

```bash
python scripts/export_supplier_data.py --root "E:\卫华供应商入围资料库" --out supplier_cache.json
```

输出：`base_info`（基础信息键值对，含多子表名称）、`qualifications`（资质清单，含 `exists`）、`documents`（入围资料清单，含 `exists` 与 `corrected_path`）、`missing`（缺失汇总）、`upload_candidates`（按常见控件名归类的候选文件）。仅依赖标准库（zipfile + xml），无需 openpyxl。
